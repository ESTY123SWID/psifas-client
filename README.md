## על פסיפס

**פסיפס** הוא מקום משותף לזיכרונות של כיתה: משפטים שנאמרו בשיעור, תמונות מטיולים וטקסים, ותגובות של חברות הכיתה. כל כיתה היא מרחב פרטי: רק מי שהצטרפה בקוד ההצטרפות של הכיתה רואה את התוכן שלה.

### איך זה עובד
- **מרחב כיתתי** — משתמשת יוצרת כיתה ומקבלת קוד הצטרפות. חברות נוספות מצטרפות עם הקוד. אפשר להיות חברה בכמה כיתות ולבחור בכל רגע את **הכיתה הפעילה**.
- **פרסומים** — שני סוגים: **משפט** (ציטוט, בדיחה, רגע מילולי) ו**תמונה** (צילום עם תיאור לא חובה). לכל פרסום יש עמוד משלו; ברשימה יש חיפוש, סינון לפי סוג ולפי "הפרסומים שלי", מיון ועימוד.
- **גלריה** — כל פרסומי התמונה של הכיתה הפעילה במקום אחד.
- **תגובות** — שמונה תגובות רגשיות (👍 ❤️ 😂 😍 🥹 😮 👏 🔥). כל משתמשת יכולה להשאיר תגובה אחת לכל פרסום, להחליף אותה או להסיר אותה.
- **דף בית אישי** — "הזיכרון של היום", פרסומים ותמונות אחרונים וחברות הכיתה.
- **פרופיל** — עריכת שם ואימייל ושינוי סיסמה.
- עברית מלאה ו־**RTL**, מותאם למחשב ולטלפון, עם מצבי טעינה, שגיאה ורשימות ריקות בכל המסכים.

### תמונות וכיוון התמונה
- לפני ההעלאה מוצגת **תצוגה מקדימה**, ואפשר ללחוץ על **"סיבוב"** כדי לסובב את התמונה ב־90° עם כיוון השעון — שוב ושוב עד שהיא עומדת נכון. הסיבוב זמין גם בהחלפת תמונה בעריכת פרסום.
- **EXIF Orientation** — תמונות מטלפון מוצגות אוטומטית בכיוון שבו צולמו (הדפדפן מיישם את נתון ה־EXIF), גם בתצוגה המקדימה וגם אחרי השמירה.
- כשבוחרים סיבוב, התמונה מסובבת בדפדפן ונשמרת **כקובץ חדש ללא EXIF** — כך הכיוון קבוע לצמיתות ואין סיבוב כפול. בלי סיבוב נשלח הקובץ המקורי כמו שהוא, ללא קידוד מחדש וללא אובדן איכות.
- הקוד: [`src/utils/rotateImage.ts`](src/utils/rotateImage.ts) ו־[`src/components/ui/ImagePicker.tsx`](src/components/ui/ImagePicker.tsx).

## סוגי משתמשים והרשאות

בפסיפס יש **שתי שכבות הרשאה נפרדות**:

| שכבה | איפה נשמרת | ערכים | על מה חלה |
|---|---|---|---|
| **תפקיד מערכתי** | `User.role` | `User` · `SystemAdmin` | כל האתר — בעיקר ממשק הניהול |
| **תפקיד בכיתה** | `ClassMember.role` | `Member` · `ClassManager` | כיתה אחת בלבד |

התפקידים בלתי תלויים זה בזה: משתמשת יכולה לנהל כיתה אחת ולהיות חברה רגילה בכיתה אחרת, ומנהלת מערכת אינה מקבלת אוטומטית גישה לתוכן של כיתות.

### משתמשת רגילה (`User`)
- **איך מקבלים:** כל הרשמה לאתר יוצרת חשבון `User`.
- **דפים:** הכיתות שלי (`/my-classes`), פרופיל (`/profile`), ובכיתות שהיא חברה בהן — דף הבית (`/home`), גלריה (`/gallery`), פרסומים (`/class/:id/posts`), עמוד פרסום וחברות הכיתה (`/class/:id/members`).
- **פעולות:** יצירת כיתה (והופכת למנהלת שלה), הצטרפות בקוד, עזיבת כיתה; כחברה בכיתה — צפייה בכל התוכן, הוספת פרסומים, עריכה ומחיקה של **הפרסומים שלה**, ותגובות.
- **חסום:** כיתות שאינה חברה בהן, עריכה או מחיקה של פרסומים של אחרות, פעולות ניהול כיתה וממשק ניהול המערכת.

### חברה בכיתה (`Member`)
- **איך מקבלים:** הצטרפות לכיתה עם קוד ההצטרפות.
- **פעולות:** כל מה שמשתמשת רגילה עושה בתוך הכיתה, כמפורט למעלה.
- **חסום:** קוד ההצטרפות, שינוי שם הכיתה, שינוי תפקידים, הסרת חברות ומחיקת הכיתה.

### מנהלת כיתה (`ClassManager`)
- **איך מקבלים:** יוצרת הכיתה היא המנהלת הראשונה; מנהלת כיתה יכולה למנות חברות נוספות למנהלות (וגם מנהלת מערכת, מממשק הניהול).
- **פעולות בכיתה שלה בלבד:** צפייה בקוד ההצטרפות והחלפתו, שינוי שם הכיתה, מינוי והורדה של מנהלות, הסרת חברות, עריכה ומחיקה של **כל** פרסום בכיתה, ומחיקת הכיתה כולה.
- **הגנה:** בכל כיתה חייבת להישאר לפחות מנהלת אחת — המנהלת האחרונה לא יכולה לעזוב, להיות מוסרת או לאבד את התפקיד עד שהניהול מועבר.
- **ההבדל ממנהלת מערכת:** ההרשאה חלה רק על הכיתה הזו, ואין לה גישה לממשק ניהול המערכת.

### מנהלת מערכת (`SystemAdmin`)
- **איך מקבלים:** אין דרך ציבורית לקבל את התפקיד. מנהלת המערכת הראשונה מוגדרת בשרת (`npm run seed:admin` או עדכון ישיר במסד הנתונים), ומשם מנהלת מערכת יכולה לקדם משתמשות אחרות בממשק הניהול.
- **דפים:** ממשק הניהול — סקירה כללית (`/admin`), ניהול משתמשות (`/admin/users`), ניהול כיתות (`/admin/classes`, `/admin/classes/:id`) — בנוסף לכל מה שמשתמשת רגילה רואה.
- **פעולות:** נתונים כלליים על האתר; חיפוש וסינון משתמשות, צפייה בפרטיהן, שינוי תפקיד מערכתי ומחיקת חשבון; חיפוש כיתות, שינוי שם, צפייה בחברות, שינוי תפקידים בכיתה, הסרת חברות ומחיקת כיתה.
- **הגנות:** אי אפשר לשנות את התפקיד של עצמך או למחוק את עצמך, אי אפשר להוריד או למחוק את מנהלת המערכת האחרונה, ואי אפשר למחוק משתמשת שהיא המנהלת האחרונה של כיתה. כלל "המנהלת האחרונה בכיתה" חל גם על פעולות מממשק הניהול.
- **מה לא:** ממשק הניהול מציג נתונים על כיתות וחברות, לא את הפרסומים עצמם. כדי לפרסם או לצפות בתוכן של כיתה, גם מנהלת מערכת צריכה להיות חברה בה.

> ההרשאות נאכפות **בשרת** בכל בקשה (מול מסד הנתונים). ה־Route Guards בקליינט (`RequireAuth`, `RequireClass`, `RequireSystemAdmin`) רק מכוונים את המשתמשת למסך המתאים.

## מבנה המערכת

```text
דפדפן ──► psifas.onrender.com  (Render Static Site — הקליינט הזה)
              │  /api/*  ──►  psifas-api.onrender.com  (Render Web Service — השרת)
              │                    ├──► Neon PostgreSQL   (נתונים)
              │                    └──► Cloudinary        (תמונות פרטיות)
```

| שכבה | טכנולוגיות |
|---|---|
| **קליינט** | React 19 · TypeScript · Vite · Redux Toolkit + RTK Query · React Router 7 · React Hook Form · Tailwind CSS 4 · lucide-react · גופני Heebo ו־Assistant |
| **שרת** | Node.js · Express 5 · TypeScript · Prisma 7 · Zod · Multer — [פירוט במאגר השרת](https://github.com/ESTY123SWID/psifas-server) |
| **מסד נתונים** | PostgreSQL (Neon בענן) |
| **אחסון תמונות** | Cloudinary — קבצים פרטיים שמוצגים דרך קישורים חתומים |
| **הזדהות** | JWT ב־Cookie מסוג HttpOnly שהשרת מנהל; הקליינט אינו שומר סיסמאות או טוקנים |

### תקשורת בין הקליינט לשרת
- כל הקריאות לשרת מוגדרות ב־RTK Query (`src/services/`), עם cache ורענון אוטומטי אחרי שינויים.
- הבקשות נשלחות עם `credentials: "include"` (ה־Cookie) ועם הכותרת `X-Requested-With`, שהשרת דורש כהגנת CSRF.
- בענן הקליינט פונה ל־`/api` באותה כתובת, והאתר הסטטי מעביר את הבקשות לשרת — כך הדפדפן עובד מול אתר אחד.

### מבנה הקוד

```text
src/
├── app/          ← Redux store
├── assets/       ← הלוגו
├── components/   ← רכיבים לפי תחום: admin, classes, posts, members, modals, layout, ui …
├── config/       ← הגדרות ניווט
├── features/     ← Redux slices (התחברות, כיתה פעילה)
├── pages/        ← מסכים: public, user, class, systemAdmin
├── routes/       ← נתיבים ו־Route Guards: RequireAuth, RequireClass, RequireSystemAdmin
├── services/     ← RTK Query: כל הקריאות לשרת
├── types/        ← טיפוסי TypeScript
├── utils/        ← פונקציות עזר (סיבוב תמונות)
└── tailwind.css  ← Design Tokens ורכיבי העיצוב הבסיסיים
```

## הרצה מקומית

**דרישות מקדימות:** Node.js 20.19 ומעלה, ו[שרת פסיפס](https://github.com/ESTY123SWID/psifas-server) שרץ מקומית.

```bash
git clone https://github.com/ESTY123SWID/psifas-client.git
cd psifas-client
npm install
npm run dev          # http://localhost:5173
```

### משתני סביבה

| משתנה | תיאור |
|---|---|
| `VITE_API_URL` | כתובת ה־API כולל `/api` |

- **בפיתוח** — מוגדר ב־`.env.development`: `http://localhost:4000/api`.
- **בענן** — `VITE_API_URL=/api` (מוגדר ב־Render לפני הבנייה). תבנית: [`.env.example`](.env.example).

### פקודות

| פקודה | תיאור |
|---|---|
| `npm run dev` | שרת פיתוח |
| `npm run build` | בדיקת TypeScript (`tsc -b`) ובנייה לתיקיית `dist` |
| `npm run preview` | הצגת הבנייה מקומית |
| `npm run lint` | בדיקת קוד עם Oxlint |
